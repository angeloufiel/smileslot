# AI review log

SmileSlot was built with an AI coding agent (Claude). This log records real problems found while building it: what went wrong, how it was caught, and what now prevents it from coming back. Each entry is something the agent wrote or assumed that was wrong, or a gap that only showed up under testing.

| # | Problem | How it was caught | Fix | Guard |
|---|---|---|---|---|
| 1 | **Trigger order bug.** A new user who signs up with an already-confirmed email got no patient record. Postgres fires triggers on the same event in **alphabetical order**, so `on_auth_user_confirmed` ran before `on_auth_user_created` had made the profile. | Database test: a confirmed patient couldn't book ("confirm your email first"). | Renamed to `on_auth_user_10_created` / `on_auth_user_20_confirmed`, with a comment explaining why. | DB test "logged-in patient always books under their own verified email" |
| 2 | **Spoofable "verified by".** The first payment trigger stamped `verified_by` only when the status changed. A secretary could edit a verified payment's `verified_by` to blame someone else. | Code review of the trigger. | The trigger now always copies `verified_by`/`verified_at` from the old row on update, ignoring client values. | DB test "payment records WHO verified it" |
| 3 | **Called a function that didn't exist.** Walk-in bookings called an RPC `new_reference_code_public` the agent invented. | Reading the action before running it; the function wasn't in any migration. | Reference codes now come from a column default, so every insert gets one automatically. | DB test "staff walk-in booking gets an automatic booking number" |
| 4 | **Session read during prerender.** With Partial Prefetching, Next.js prerenders using cookies but forbids reading the clock. The Supabase client checks token expiry with `Date.now()`, so every signed-in page logged an error. | Server logs during the end-to-end run. | `createClient()` calls `connection()` so session reads always happen at request time. | E2E run checks the server log has zero errors |
| 5 | **Filter injection risk.** Dashboard search text went straight into a PostgREST `or(...)` filter. A comma or parenthesis in the search box would change the filter's meaning. | Code review. | Search text is reduced to letters, numbers, spaces and `@.-` first. | Documented in SECURITY.md |
| 6 | **Linking guest bookings too early.** The obvious approach links past guest bookings on sign-up. But anyone can sign up with someone else's email, so they'd see that person's appointments. | Threat modelling the guest flow. | Link only when `email_confirmed_at` becomes set. | DB test "unconfirmed signup does NOT get access to the guest's past bookings" |
| 7 | **Overlapping calendar entries.** Two dentists' appointments at overlapping times were drawn on top of each other. | Screenshot review. | One lane per dentist within each day. | Visual check |
| 8 | **Booking page wider than the screen.** The 14-day date strip pushed the CSS grid wider than the viewport on desktop. | Screenshot review. | `minmax(0, 1fr)` and `min-w-0` on the grid column. | E2E "no horizontal scrolling" check |
| 9 | **Status rules in two places.** The dashboard decides which buttons to show; the database decides what's allowed. They could drift apart. | Design review. | A unit test parses the trigger's rules from the SQL file and compares them with the UI's table. | `npm test` |
| 10 | **Service role couldn't create bookings.** The reference-code column default calls a function that was only granted to logged-in users. Admin scripts and server code using the service role failed with "permission denied". On Supabase this would have broken the demo seed. | Running the seed script against real Supabase Auth + PostgREST. | Granted the function to `service_role` too. | DB test "service role inserts get a reference code" |
| 11 | **Multi-row insert sent nulls.** Inserting several customers at once, supabase-js sends `null` for keys missing from some rows instead of using the column default, which broke `is_vip not null`. | Seed script failure. | `insert(rows, { defaultToNull: false })`. | Seed script runs in the local-stack check |
| 12 | **The live demo would have been empty.** Fresh deployments had accounts but no appointments, so a reviewer would see blank dashboards. | Reviewing screenshots of a fresh stack. | The seed script adds 9 realistic sample appointments (past, upcoming, pending deposit, no-show) when the clinic is empty. | Visual check |
| 13 | **A homepage time could silently vanish.** If a homepage time button was clicked just as it passed the 2-hour minimum notice, the booking page showed no selection and no explanation. | An end-to-end run that happened to hit the boundary. | The booking page now says the time was taken or is too soon and asks for another. Times are compared by value, not string format. | E2E booking flow |
| 14 | **A role change could report success without saving.** The old role form showed "Role updated" without checking how many rows changed, and the page didn't refresh, so the label and the real role could disagree. | A screenshot from the live demo (the secretary appeared as Patient). | Staff editing moved to a dialog with a clear "will change from X to Y" warning; the action uses `.select()` and fails loudly if nothing was saved. | E2E "Rhea is still a secretary" after editing another person |
| 15 | **Reference codes were hard for non-technical patients.** `SS-7K4MQ2XP` mixes letters and digits that look alike (0/O, 1/I). | User feedback. | Migration 600 switches to 8 digits shown as `4827-3159`; lookups ignore dashes and spaces; old codes are converted in place and audited. | DB tests for dash/space lookups; E2E "typed with a space is found" |
| 16 | **Closing "the morning" from opening time would miss early walk-ins.** Staff can book outside online hours (e.g. 7:00), so a close that started at opening time wouldn't list those patients. | Writing the E2E test for the affected-patients warning. | Morning = midnight to noon, afternoon = noon to midnight; the warning lists every active booking in that range. | E2E "patients already booked in that time are listed" |
| 17 | **Browser alert boxes.** Confirmations used `window.confirm`/`prompt`, which show "localhost says…" and look broken to clinic staff. | User feedback. | One in-app `ConfirmDialog` (native `<dialog>`, Esc to close, reason field when needed). | E2E fails if any browser dialog appears |
| 18 | **Clinic name never changed.** Saving Settings worked, but the header, sidebar, sign-in page and page titles had "Harborview" typed into the code. | User report from the live site. | One cached `getBranding()` (tagged `clinic-branding`) feeds every header and title; saving Settings calls `updateTag` so the change shows at once. | E2E renames the clinic and checks the dashboard menu and the public header |
| 19 | **Receipts over 1 MB failed silently.** Next.js limits Server Action uploads to 1 MB by default, but the form promised 5 MB. Also, Vercel accepts at most 4.5 MB per request. | Adding the logo upload and reading the Next.js docs for the upload limit. | `serverActions.bodySizeLimit: "4.4mb"`, receipts capped at 4 MB, checked in the browser before sending. | Unit-level limits in `validation.ts`; documented here |
| 20 | **Instant sign-up would have leaked guest bookings.** Turning off email confirmation means the old "link guest bookings on confirmation" rule would link them on sign-up, to anyone who typed that email. | Threat-modelling the change before making it. | Separate guest/account customer records and a booking-number claim (`claim_booking`). | DB tests "a new account with a guest's email does NOT take over…", "cannot claim a booking made with a different email" |
| 21 | **Forms emptied themselves after an error.** React 19 resets a form after its action runs, so a sign-up error made people retype everything. | Screenshot review. | Failed actions return the typed values (never passwords) as default values. | E2E "the form keeps what was typed after an error" |

## How changes were checked

- Database rules: `npm run test:db` attacks the schema as guest, two patients, two dentists, a secretary, the owner and the service role (93 checks), including 10 simultaneous bookings for one slot.
- App: typecheck, lint, 21 unit tests, production build.
- End to end: a real browser against real Supabase Auth and PostgREST, every role (88 checks), plus screenshots reviewed at desktop and mobile widths.
